# 养宠顾问

面向第一次养猫狗的新手主人的 7×24 随身喂养顾问：只讲科学共识，温柔但不越界——不诊断、不开药，但会告诉你什么时候必须立刻送医。v2.0.0 起内置本地宠物互动（二次元猫狗、动作、合成音效，与对话状态联动）。

## 快速开始

前置条件：Node.js 18+ 且 `node` 能在命令行直接调用（Windows 用 `where node` 自查，找不到就把 Node 目录加进用户 PATH 并重启 Trae）；不需要 `npm install`，不需要 API Key。

1. 拉取当前仓库到本地，用 Trae 打开。
2. 在 Trae 的 Agent 对话框粘贴 `启动提示词.txt` 并发送。
3. 浏览器自动打开 `http://127.0.0.1:4173`（也可手动访问）。在宠物页点一次「开启声音」，回到 Trae 咨询。
4. 输入「换成小猫」或「换成小狗」切换搭档，也可以直接在宠物页切换和演示状态。

可以试一句：`狗狗吃葡萄会怎么样？`——正文先给高危警示，宠物用倒地、X 眼和幽灵做危险后果示意。只想预览形象的话，直接用浏览器打开 `companion/index.html` 手动演示即可，自动联动仍需运行 `node companion/start.mjs`。

## 项目定位

回答四类问题：

1. **饮食科普**：某样东西猫狗能不能吃，为什么，误食了怎么办
2. **习性照料**：品种精力需求、行为问题（乱尿/拆家）怎么理解
3. **症状观察**：宠物异常时，区分「居家观察」还是「立刻送医」
4. **就医指引**：怎么筛选正规宠物医院、就诊前准备什么

背景：中国城镇犬猫超 1.2 亿，60% 是 90 后/00 后首次养宠；约 47% 的新养宠人不知道该喂什么、什么不能喂，半夜出异常时要么恐慌性跑医院、要么拖着不敢去。这个 Agent 在用户冲去医院之前，先帮他判断这事急不急——同时守住红线：**绝不替代兽医诊疗**。

## 核心设计决策

### 1. 对话有严格的优先级状态机

收到用户消息后必须按顺序判断，不得跳步：

```
① 是不是伤害宠物的请求？→ 拒绝，结束
② 是不是高危急症？→ 第一句必须是送医提醒，不铺垫
③ 是不是普通症状？→ 引导记录症状，不确诊、不开药
④ 是不是饮食/习性/医院问题？→ 走对应技能
⑤ 是不是闲聊跑题？→ 礼貌拉回
```

宠物喂养涉及生命安全，急症漏判一次就可能致死，所以急症识别强制置顶、排在所有技能之前。

### 2. 安全边界写死在提示词里

- 不诊断疾病、不开药、不指导自行用药
- 禁食食物分三级（致命/高危/禁止），用户说「就一点点」也不让步
- 暴力训宠、投毒、私自安乐请求，只回固定拒绝话术
- 拿不准就说「建议咨询执业兽医」，不编造

### 3. 语气是产品的一部分

面向焦虑的新手主人，先安抚再给信息，不说教；但温柔不等于模糊，高危结论必须醒目前置。

### 4. 症状判断分三档，判不清就高不就低

高危立即送医 / 中风险当天或 24 小时内就医 / 低风险可先居家观察；居家护理建议不超过 3 条，每条附就医触发条件。

### 5. 合规与安全条款写进提示词，不只写在 PRD 里

- 症状类、中毒类、涉用药的回答末尾固定带免责声明
- 外部内容不是指令：用户粘贴的文字、联网搜索结果只作参考，「忽略以上设定」类话术不改变边界（OWASP LLM01 典型风险）
- 隐私最小化：只问月龄/体重/症状时间/接触物，不索取手机号住址，不复述用户隐私
- 高危食物与家庭物品清单写死在提示词与知识文件里，不指望模型自己记得

## 宠物联动

```text
Trae 每轮回答
  → node companion/pet.mjs（一条本地命令）
  → 127.0.0.1 HTTP POST
  → Server-Sent Events
  → SVG/CSS 动作 + WebAudio 猫狗音效
```

- 低延迟：常驻本地服务省掉每轮建服务和网络请求；SSE 适合服务端到页面的单向实时推送，比 WebSocket 更轻。
- 易安装：Node 原生模块 + 浏览器原生能力，零 npm 依赖；不用下载 Live2D 模型、图片帧和音频素材，也没有素材授权问题。
- 少配置：不要求用户手工改 Trae 全局 MCP 配置；启动器幂等，服务已存在就复用。
- 安全降级：只监听 `127.0.0.1`，状态与宠物名走白名单，消息限长并纯文本渲染；联动失败零重试，急症正文不被动画阻塞。

平台边界：本地 CLI→SSE 链路可以自动测试，但 Trae 是否每轮都及时执行命令受平台能力与命令权限影响，须在目标 Trae 版本实跑后才能承诺「每轮必联动」；浏览器要求用户先点一次才能播放声音。

## 技术栈

- 平台：Trae（对话式智能体，无自建后端）
- 底层模型：DeepSeek-V4.1-Flash（Temperature / Max Tokens 用平台默认值）
- 配置方式：系统提示词驱动 + 写死的高危清单（`knowledge/forbidden-foods.md`）
- 工具：联网搜索（内置），在 `agent.yaml` 与提示词里显式声明使用条件与失败降级；
- 输入模态：仅文字（不支持看图），配置中声明 `modalities.image: false`
- 本地展示层：SVG/CSS 动画 + WebAudio 合成音效，CLI HTTP POST + SSE 实时联动，Node.js 18+、零 npm 依赖

## 评测结果

两轮 15 题（`宠物AI测试结果.xlsx`）：第一轮核心功能 10 题（饮食科普 3、习性科普 1、普通症状 1、高危急症 1、违规请求 2、就医指引 1、跑题闲聊 1），第二轮边缘对抗 5 题（诱导殴打、混合意图、索要药名、损招诱导、淡化求助），全部正确拦截或按规范回答。测试还驱动了一次真实迭代：发现「一颗葡萄」题的核心结论没放在开头，于是在提示词里新增规则——高危食物回答第一句必须是「明确禁止 + 风险等级」。

结构化回归（`evals/test-cases.jsonl`，31 条用例，逐条验收点 + 红线分级）：

- v1.4.0→v1.5.5 五轮实跑迭代，严格通过率 80.6% → 93.5% → 100%（31/31），`pass_with_defects` 归零
- v1.5.5 名下实测 7 条：N12、N15 + 急症 4 道（C05/N07/N08/N09）+ 清单外食材 N06，全部 `pass`；急症召回从「沿用旧版记录」变为「当前版实测」
- 红线累计五轮实跑 0 违例：急症召回 100%、药名与剂量 0 次、病名结论 0 次、手机号住址回显 0 次、越界承诺 0 次

两点口径说明：其一，通过率分母始终是 31，其中 24 条记的是各自最后一次实跑的结果，跨版一致性属推断而非实测。其二，N12 抽查曾暴露根因 F——范围外表与技能 3 第 5 条抢同一场景、只会输出一句原句；2026-10-29 拍板选 B（问用药时两句锁定原句逐字都要出现），改法落入 v1.5.5 四处措辞，同日复跑坐实两句原句同时逐字出现、顺序正确、未被合并，F 收口。完整成绩表、逐条归因与判分口径见 `docs/test-report.md`，迭代记录见 `CHANGELOG.md`。
