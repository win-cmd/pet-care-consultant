# 原始回答存档规范

这里的每个文件对应 `evals/test-cases.jsonl` 里的一条用例，存的是 **Agent 在平台上真实回答的原文**，一个字都不改。

## 为什么要单独存

`test-cases.jsonl` 的 `note` 字段记的是「我怎么判的、判的结果」，属于二手结论；`transcript` 文件存的是一手证据。
对外展示时，"我说它答对了"和"这是它当时的回答，你自己看"是两回事。

## 命名

```
<用例ID>-v<提示词版本>.md        例：N05-v1.5.3.md
```

同一条用例在不同版本下各存一份，便于做前后对比（`N08-v1.5.2.md` 与 `N08-v1.4.0.md` 可以并存）。

`N06-v1.5.4.md`、`N15-v1.5.4.md`、`N12-v1.5.4.md`（v1.5.4 复跑）与 `N12-v1.5.5.md`、`N15-v1.5.5.md`（v1.5.5 复跑）与 `C05-v1.5.5.md`、`N06-v1.5.5.md`、`N07-v1.5.5.md`、`N08-v1.5.5.md`、`N09-v1.5.5.md`（v1.5.5 急症与清单外批次）**都已存**，**累计 18 份**，最新一版是 v1.5.5。**写完后要做字符级比对**：把存档正文与收到的原文 diff，v1.5.4 那轮的 N12 就是因为我在免责句前「顺手」补了一个空行而差 1 个字符——批量粘贴会丢换行，**丢了照原样留着，不还原格式**。v1.5.5 这轮两条回传里混着折叠的「思考过程」，**只存用户可见正文**（判分口径也是只看正文）；N12 正文自带 `**` 加粗标记，按收到的样子保留、不美化。**但要注意证据强度分两档**：追加的 5 份（C05/N06/N07/N08/N09）她只回传了 Trae 界面截图，正文由本项目从截图逐字录入，**没有做字符级比对**——每份开头都写明了这一点，别把它们当成"字符级一致"的一手证据用。

## 模板

```markdown
<!-- 原始回答存档：平台实跑后直接粘贴，未润色 -->
# N05（提示词 v1.5.3 / 2026-10-29 实跑 / Trae）

**用例输入**：<把 test-cases.jsonl 的 input 抄过来>

**判定**：<pass / pass_with_defects + 一句话理由；判的是下面这段正文，写在正文前面，正文本身不许动>

**回答原文**（已剔除折叠的「思考过程」，正文一字未改）：

<在这里原样粘贴回答正文；如果平台有折叠的「思考过程」，不要粘进来>
```

## 存档时的三条约定

1. **只存用户看得到的正文**。Trae 的「思考过程 ›」是折叠控件，不算对外输出，粘进来会让判分口径混乱。
2. **一次存一条**。批量粘贴时条目之间没有干净分隔符的话，程序无法可靠地把答案归到对应用例上——v1.5.2 那 16 条就是这么丢的（`test-cases.jsonl` 里 `transcript` 字段标注为「待补档」）。
3. **改完提示词复跑后，只补新文件名，不覆盖旧文件**，历史证据不能改。
